# 文档地图

这个目录里有六份文档。**这份文件是入口**——先看它，再决定读哪份。

五张图（`*.png`）都是各文档正文引用的实测截图/对比图，不单独看。

---

## 六份文档分别讲什么

| 文档 | 讲什么 | 什么时候看 |
|---|---|---|
| [`acceptance.md`](acceptance.md) | **三条需求的验收判决**。两个场地、两轮，含明确没通过的 | 想知道"到底做到了没有" |
| [`nav2.md`](nav2.md) | Nav2 调参细节、定位精度实测、被踩过的坑 | 想改参数、排查导航问题 |

| [`real_robot_plan.md`](real_robot_plan.md) | **实车迁移计划**：驱动层、验证手段、安全、分阶段推进 | 准备上车 |
| [`real_robot_params.md`](real_robot_params.md) | **实车参数标定操作手册**：逐项怎么量、填哪 | 上车后动手标定 |

## 按目的选阅读顺序

**① 我只想把它跑起来**

```
仓库根的 ../../../README.md 的"快速开始"
  → nav2.md 的「怎么跑」
  → 出问题再看 nav2.md 的「⚠️ 踩过的坑」
```

**② 我想知道这套东西做到了什么程度**

```
acceptance.md（先看开头的结论表）
  → 对哪条有疑问，再点它给的"出处"进 nav2.md / slam.md 看细节
```

**③ 我准备搬到真车上**

```
real_robot_plan.md（先看第 0 节结论速览 + 第 8 节阻塞项）
  → 第 3 节讲标定顺序
  → real_robot_params.md 逐项照做
  → 第 4 节讲验证手段为什么要换（这条最容易漏）
```

## 权威出处：同一个问题该信哪份

文档是逐步长出来的，**早期有过两处内容重复**，已经合并。为了让它们不再长回去，
这里明确每类信息**唯一的出处**：

| 想知道 | 唯一出处 | 别处怎么写 |
|---|---|---|
| 三条需求过没过 | `acceptance.md` | 只给结论摘要 + 链接 |
| 某个实测数字的上下文 | `acceptance.md` 的表格 | `nav2.md` / `slam.md` 讲细节，不重复表 |
| 参数当前值 / 实车怎么量 | `real_robot_params.md` | `nav2.md` 只讲"为什么需要这个参数" |
| 脚本怎么用、怎么判读 | `tools.md` | 别处只提名字 |
| 实车要做什么 | `real_robot_plan.md` | `nav2.md` 的「已知限制」只讲仿真侧 |
| 上游默认值为什么不能照抄 | `nav2.md` 的「配置里几处必须跟着实车改的地方」 | —— |

**已合并的两处**（留个记录，避免以后又写重）：

1. **skid-steer 有效轮距标定**——完整数据表和标定步骤统一在
   `real_robot_params.md` 第二节；`nav2.md` 只保留推导（为什么需要 `b_eff`）。
2. **障碍物避让的根因分析**——完整四步推导统一在 `acceptance.md`；
   `nav2.md` 只保留一句话结论。

## 写文档时注意（给以后的自己）

* **新增文件后必须重新 `colcon build --symlink-install`**。`install/` 里是按**文件**建的
  符号链接，不是整目录链接，所以 `install(DIRECTORY docs)` 虽然涵盖了新文件，
  也要跑一次 build 才会生成链接。
* **数值只写一处**。要引用就写"见 X 文档"，不要复制表格——上面那两处重复就是这么来的。
* 说"实测"就要给得出**判读口径**（用什么量的、真值从哪来），否则读者无法判断可信度。
* 没测的东西要**显式写出来**，`acceptance.md` 的「已知的残余风险（明确没测）」是模板。
